# Automatic Learning Documentation
## Objective
Maintain a learning journal for completed development and testing tasks in this repository.
## Rules
1. After completing a meaningful task, create a Markdown file inside the `learnings/` directory.
2. Create the directory if it does not exist.
3. Filename format: YYYY-MM-DD-short-task-description.md 
4. Use lowercase kebab-case for task descriptions.
5. If a file with the same name exists, update it instead of overwriting unrelated content.
6. Never invent test results or successful outcomes.
7. Do not include passwords, tokens or personal data.
8. Do not create learning files for trivial changes.
## Each learning file must include
# Task Title
## Date
## Objective
## Tools and Technologies Used
## Steps Performed
## Code Examples
## Challenges Faced
## Solutions Implemented
## Key Learnings
## Testing and Verification
## Future Improvements
## Completion workflow
- Complete the requested task.
- Run relevant tests where possible.
- Document the actual work in `learnings/`.
- Include the learning file in the changes.
- Mention the created file in the final summary.
- Do not commit or push unless authorized.
